# Reconstruction adapter boundary

This package adds three backend building blocks:

- `ingest.py` verifies source checksums, applies EXIF orientation, normalizes still images (including HEIC/HEIF) to JPEG, and writes a manifest binding each staged image to the upload ID, side assignment, and source checksum. It does not extract video frames or infer camera calibration.
- `sfm_adapter.py` invokes the repository's existing `capture-splat sfm` COLMAP/GLOMAP runner with a conservative CPU-capable sparse-SfM profile, then requires the sparse camera and point artifacts. It produces camera/point-cloud evidence, not a room surface mesh.
- `scale_registration.py` calculates a weighted uniform scale from measured distances **only when** corresponding reconstructed 3D endpoint pairs are supplied. It reports per-anchor residuals and holds inconsistent anchors. It cannot locate the measured endpoints in photographs.

## Runtime prerequisites and current integration state

The adapter requires the `capture-splat` console command and a compatible COLMAP binary. The local development setup has `capture-splat` installed in the active Python environment and includes the official COLMAP 4.2.1 no-CUDA Windows package under the git-ignored `tools/colmap-4.2.1/` folder. The adapter discovers that local package automatically; deployments can set `COLMAP_BINARY` to an approved executable path. The job's CPU matcher mode is explicitly enabled. EXIF-normalized staged images receive a small centered crop to a common size because COLMAP's single-camera mode requires equal image dimensions; source uploads remain unchanged and the ingest manifest records each original and staged size. A first four-screenshot run reached COLMAP but did not find a stable initial camera pair, so add more overlapping, sharp room photos and retry. Successful SfM yields camera poses and sparse 3D points only, with no metric-scale registration or room surface mesh.

The adapter is not yet registered as an API job handler and reconstruction artifacts are not persisted as project revisions. Intake stores optional room length/width, labeled doors/windows/other openings, a measurement description, endpoint labels, a side-photo reference, source, user confidence, optional normalized image-space endpoint picks with the source filename, an optional floor-plan/sketch upload, and an optional PLY point cloud. PLY headers are checked at upload completion, and the configured upload cap applies. Sensor data is preserved as evidence but is not interpreted by reconstruction. The API can return a provisional rectangular wireframe when length, width, and ceiling height are known; that draft uses entered dimensions only, marks zero image coverage, and requires human review. Image picks are not matched to reconstructed 3D endpoint correspondences; therefore metric scale registration cannot run end to end. Dense MVS and image-derived architectural surface extraction are not implemented. Keep the reconstruction job disabled until these contracts and worker integration are complete.
